# 简历项目经历（按“殷宇轩秋招1.3”格式）

## 推荐版本

外贸询盘处理 Agent | 2026.08 – 2026.09 | 个人项目，独立开发 | github.com/yyx-lhz/ecommerce-customer-service-agent

Python + FastAPI + LangGraph + OpenAI Structured Output + Pydantic + Embedding + Vector Retrieval + HTML/CSS/JavaScript

- 针对外贸销售人工阅读英文询盘、反复确认需求并跨系统查询产品信息效率低的问题，设计询盘处理 Agent，将原始消息保存、需求抽取、完整性判断、主动澄清、产品检索、业务查询和英文回复编排为端到端流程，并通过 FastAPI 暴露分阶段及一键处理接口。
- 设计可替换的 Inquiry Parser 与 Pydantic Schema，抽取产品类型、数量、国家/地区、规格、目标价格和交付条件；支持 OpenAI Structured Output 与离线规则解析双模式，对缺少产品、数量或目的国家的询盘自动转入澄清分支，避免在信息不足时直接生成报价。
- 构建 Embedding 产品知识库，将产品名称、别名、描述及规格建立向量索引，通过 Top-K 语义召回获得候选产品，再结合 MOQ、库存、规格和目标价格进行二次匹配，输出最佳 SKU、匹配分数及可解释理由。
- 将价格、库存、交期和规格封装为独立业务工具，回复生成模块只使用检索结果与工具返回值组织英文报价草稿，降低模型直接编造价格和交付承诺的风险；使用 LangGraph 管理完整询盘与信息缺失两类分支，并保留执行轨迹便于排查。
- 建设询盘 Benchmark 与自动化评测脚本，覆盖信息抽取准确率、意图分类准确率、Recall@K、工具调用准确率和端到端完成率；开发可视化工作台，集中展示结构化字段、候选产品、匹配理由、业务工具结果、英文回复和 Agent Trace，形成可演示的完整业务闭环。

## 面试口述版

我做的是一个外贸销售询盘处理 Agent。海外客户发来邮件后，系统先把自然语言抽取成结构化采购需求，再检查产品、数量和目的国家是否齐全；信息不足就生成英文澄清问题，信息完整才进入产品向量检索和匹配。匹配完成后，通过价格、库存、交期和规格工具获取业务事实，最后生成销售可以审核发送的英文回复。这个项目里我重点解决了两个问题：一是用 Workflow 控制必经步骤，避免模型跳过完整性判断；二是让报价和库存来自工具，而不是让 LLM 自己生成。前端会把每一步中间结果和执行轨迹展示出来，方便演示和排查。
